# 在其它项目复用品牌评审

## 三种一行委托

- 新项目：`用 logo-brand-designer 为当前项目做首个 logo；先发现可用工具能力并读取项目资料，交付 token、理念、完整 SVG、独立评审 HTML 与 screenshots/，没有旧图就不填 oldAsset。`
- 重设计：`用 logo-brand-designer 重设计当前项目标识；保留用户确认的识别线索，附真实旧图对照与深底版本，保留独立评审页和标明来源及测试范围的 screenshots/。`
- 既有 token：`用 logo-brand-designer 按我提供的 token、理念与 SVG 完善标识；先沿用并核对来源，把调整建议与已确认要求分开记录，交付离线评审页、完整任务及真实 screenshots/。`

## 工作流与产物

1. 先实际调用当次环境的能力发现工具/工具帮助，按返回结果自主选择可用的浏览器、渲染器与模型。模型调用遵循用户授权及费用限制，不固定型号、分辨率或账号能力；直接写 SVG 不需要生成模型。本次任务禁止付费模型就不调用。工具不可用时记录阻塞，不能把 prompt、任务复制或计划当成调用成功。
2. 读取 README、生产主题与品牌素材，记录每条 token/理念的来源。用户给定、项目既有、素材测量、本次建议分别标注；缺证据写未核验。`userDecisions` 只放真实的用户输入/确认，`recommendations` 放未确认建议，`rationale` 本身不代表批准。
3. 在交付目录内组织 manifest 和本地素材。建议树形为 `delivery/{manifest.json,assets/,review.html,screenshots/}`；manifest 所在目录为输入路径边界。若生产资料在目录外，用 `sources` 的可访问生产链接引用，或经授权复制必要资料到交付目录；不要用 `../` 绕过边界。避免将测试素材或重复图放进内容仓触发 CI。
4. 用下面的标准库脚本构建页面；它不调用模型、不下载资源、不依赖图床 `tools/`。生成成功仅代表结构检查成功，继续真实渲染及浏览器检查。
5. 在浏览器打开实际生成的 HTML，检查暗/浅/棋盘、32/64/128、旧图缺省、darkAsset 加载、SVG/JSON 下载、完整任务复制。对剪贴板检查结果，不只检查按钮点击。复制拒绝时必须显示“自动复制失败”，提供可手动复制的完整文本；不能返回“已复制”。保存页面和原始素材/manifest，便于后续继续设计。
6. 真实截图保存到该次交付目录 `screenshots/`。截图来自当次打开的评审页/实际渲染器，不拿已有图片冒充截图。交付说明逐项写出文件名、来源页面或渲染命令、素材版本或 SHA-256、背景、图标 CSS px、视口与设备缩放（已知时）、测试动作和结果。至少实际查看浅/深 32px，并保存相应证据；64/128 和棋盘实际做了哪些就写哪些，未做明确列出。脚本不自动生成截图，也不验证输入中的截图声明。

## 构建命令

`SKILL_DIR` 指本次实际读取的 skill 目录（项目或全局）；`DELIVERY_DIR` 指独立交付目录。从任何工作目录调用都可以：

```bash
python3 "$SKILL_DIR/scripts/build_review.py" \
  --manifest "$DELIVERY_DIR/manifest.json" \
  --out "$DELIVERY_DIR/review.html"
```

需要 Python 3.9+，没有第三方包。先参考 [manifest-example.json](manifest-example.json) 填真实资料；示例是契约说明，**未附图像和源码占位文件，不能原样运行**。校验失败退出 1，用法错误退出 2，检查通过退出 0；失败不写新的 HTML。若输出位置已有旧页面，失败会保留旧文件，必须根据退出码判断，不得用旧页面声称本次生成通过。`--out` 是调用者明确选择的输出位置，可在 manifest 目录外；只允许 `.html`，不允许覆盖 manifest/素材/来源文件或直接输出到符号链接。

## Manifest 契约

顶层是 `{"projects": [...]}`，非空数组支持多个项目。每个项目：

| 字段 | 约定 |
| --- | --- |
| `id`, `name` | 至少提供一个非空字符串；另一项缺省时沿用，id 不重复。 |
| `sourceFiles` / `sources` | 可同时提供，数组或单字符串；条目为字符串或 `{ "path": "README.md", "label": "…" }` / `{ "url": "https://…", "label": "…" }`。本地条目须存在且在 manifest 目录内；HTTP(S) 只是来源链接，不抓取、不代表已核验。省略会明确显示未记录。 |
| `tokens` | 必填 `primary/accent/onLight/onDark/background`；值为 3/4/6/8 位 hex，background 也可为 `transparent`。前景命名表示相应背景上的图形颜色。可增加其它有来源的 hex token。 |
| `tokenSources` | token 名到非空来源说明的映射；记录分类、生产文件/行号/链接或测量依据。不填时每项显示“未标注来源，未核验”，不会捏造证据。 |
| `rationale` | 字符串或字符串数组；写 1–3 句产品能力与图形之间的联系，标明本次解释或已知来源。缺省显示未记录。 |
| `userDecisions` | 可选字符串/字符串数组，仅真实用户给定/确认的要求。 |
| `recommendations` | 可选字符串/字符串数组，未获确认的建议。 |
| `asset` | 必填本地 `.svg/.png/.webp` 路径；新设计最终交付应为 SVG。 |
| `darkAsset` | 可选，同格式本地路径；缺省或 null 复用 asset。深底切换加载它；棋盘使用主版本。 |
| `oldAsset` | 可选，同格式本地路径；缺省或 null 明确显示无旧图，首次设计合法，不虚填旧图。 |

所有本地输入路径以 manifest 目录为根；禁止绝对路径、`..`、Windows 盘符、反斜杠、URL 素材及越界符号链接。单个文件（含 manifest）上限 8 MiB；它是评审工具的内存界限，不代表内容仓允许该大小入仓。原 JSON 下载保留相对路径，搬迁时须带齐素材；“完整 JSON”另含实际素材 data URI、SVG 全文、SHA-256 和结构检查结果，是离线归档包，并非直接重输给构建器的 manifest。

## 页面能力与验证边界

HTML 内嵌全部 SVG/PNG/WebP，无 CDN、字体、联网脚本或运行时 fetch。CSP 只允许内嵌且哈希匹配的页面逻辑及 data URI 图像，外部来源只有用户主动点击才访问。输入文本用 DOM `textContent` 展示，SVG 不插入页面 DOM。页面提供背景与 32/64/128 切换、可选新旧图、token 来源、理念、原素材下载（SVG 保留全文）、原 manifest 和完整 JSON 下载；完整任务包含实际 SVG/位图、token 证据、用户决策、未确认建议、页面补充及验证边界。页面补充不会自动持久化，请复制保存。

SVG 采用静态元素/属性白名单：正方 viewBox，存在可访问名称与 title，`role="img"`；拒绝脚本、事件、外链、位图、文字/字体、filter、foreignObject、style/CSS、动画、DTD/实体、非法/缺失/循环内部引用。渐变、裁切、mask 和静态内部引用可用。既有 SVG 若带编辑器元数据或 style，先有依据地清理成自包含 presentation attributes；不静默剥离再假称原文件通过。PNG/WebP 只检查文件头尺寸是否为正方形，不完整解码、不检查像素；页面为位图生成替代文字，位图不适用 XML title/aria 校验，也不能代替最终 SVG。

结构检查不能证明 alpha 透明、非空图、留白、主体比例、颜色是否对应 token 或小尺寸可辨。用 `rsvg-convert` + Pillow 或当次可用等价渲染器检查真实 RGBA 与 alpha 边界，记录实际命令和结果；浏览器截图用于目视背景/尺寸验收。缺工具/未渲染/未目视就明确未完成，不能把 HTML 生成、PNG/WebP 文件头检查或看见棋盘等同像素透明证明。16px、任意彩底、色觉模拟等未做项目同样如实列出。

## 维护与同步

保持 skill 名字 `logo-brand-designer`。在项目副本更新完整目录后，先列出/比较全局目标内容；对将覆盖的既有文件先读取并理解差异，再将 `SKILL.md`、`scripts/`、`references/` 等全部同步到全局同名目录。不要只复制入口文件，不使用删除选项，也不要删除目标原有的用户文件；验证同名文件内容一致。更新无需提交、推送、发布或重复运行其它项目 CI。
